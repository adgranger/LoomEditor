## Goal

Chinese, Japanese and Korean input methods, dead keys and the emoji panel work in the Avalonia `LoomEditor` on Windows (TSF), macOS (`NSTextInputClient`) and Linux (IBus / Fcitx
through Avalonia). The composition is drawn as in WinUI, and the candidate window sits at the caret.

## Design decisions (already made — do not change)

- Mapping of the WinUI model onto `TextInputMethodClient`: `SurroundingText` = the text of the caret's line, the selection mapped into it (the `TextRequested` handler of WinUI
  gives the same text window); `CursorRectangle` = the caret rectangle in editor coordinates (WinUI `LayoutRequested`); `SetPreeditText(text, cursorPos)` = the composition
  update (WinUI `TextUpdating` while composing); committed text arrives through the editor's `TextInput` event and goes to the same View call as WinUI's
  `CompositionCompleted` path. `Selection` set by the IME (reconversion) → `EditContextModel` as WinUI's `SelectionUpdating`.
- Raise `TextViewVisualChanged` / `CursorRectangleChanged` / `SurroundingTextChanged` where WinUI calls `NotifyLayoutChanged` / `NotifyTextChanged` / `NotifySelectionChanged`.
- `SupportsPreedit = true`, `SupportsSurroundingText = true`.
- Read-only editor: the client is still given (so an IME does not type into another control), but commits are ignored, as WinUI.
